## ReSOlve Benchmark Dataset

This folder contains a single file named **`ReSOlve.xlsx`**, which includes **790 instances** across **four quartiles** (based on comment counts).  
Each instance has been **manually annotated** under two categories:

- **IA** – Improvement-related comment that was addressed  
- **GC** – General comment  

Additionally, for each instance, the following versions are included:

- **Initial Version** – The answer just before the first improvement-related concern was addressed.  
- **Revised Answer Version** – The answer after addressing all improvement-related concerns.

---

### File Structure of `ReSOlve.xlsx`

| Column Name | Description |
|--------------|-------------|
| **answer_id** | Unique identifier for each Stack Overflow programming answer instance |
| **question_id** | Identifier linking the Stack Overflow answer to its corresponding question |
| **quartile** | Indicates which quartile (based on comment counts) the instance belongs to |
| **labelled_comments** | User comments manually labeled as either *IA* (Improvement-related that addressed) or *GC* (General comment) |
| **question** | The programming-related question corresponding to the answer |
| **initial_answer** | The version of the answer before any improvement-related concerns were addressed |
| **revised_answer** | The improved version of the answer after addressing all identified concerns |

Each row in `ReSOlve.xlsx` represents a unique **answer-question pair**, allowing analysis of **how improvement-related feedback** influences **answer revision quality** over time.

## (2) Identifying Improvement-Related Concerns in Comments with LLMs (RQ1)

This folder contains **four files**:

- `DeepSeek.xlsx`  
- `Gemini.xlsx`  
- `Gpt.xlsx`  
- `LLaMA.xlsx`

Each file presents evaluation findings of detecting improvement-related concerns using the following LLMs:

- **DeepSeek-V3.1-Reasoner**  
- **Gemini 2.5 Flash**  
- **GPT-5**  
- **LLaMA-4 Maverick**

---

### File Structure

| Column Name | Description |
|--------------|-------------|
| **answer_id** | Unique identifier of the Stack Overflow programming answer analyzed |
| **question_id** | Identifier linking the Stack Overflow answer to its corresponding question |
| **quartile** | Indicates the quartile grouping based on the number of comments |
| **labelled_comments** | The original user comments labeled as either *IA* (Improvement-related) or *GC* (General comment) |
| **input_comments** | The comment input text provided to the LLM for concern identification |
| **concerns** | Concerns captured by the respective LLM from the provided comments |
| **True Positive (TP)** | Instances identified as *IA* by the LLM and originally labeled as *IA* |
| **True Negative (TN)** | Instances identified as *GC* by the LLM and originally labeled as *GC* |
| **False Positive (FP)** | Instances identified as *IA* by the LLM but originally labeled as *GC* |
| **False Negative (FN)** | Instances identified as *GC* by the LLM but originally labeled as *IA* |


From the classification outcomes above, the following metrics were computed for performance evaluation:

- **Accuracy**  
- **Precision**  
- **Recall**  
- **F1 Score**  
- **Specificity**  
- **Matthews Correlation Coefficient (MCC)**

These metrics were used to assess how effectively each LLM identifies improvement-related concerns within developer feedback comments.

## (3) Improvements Comparable to Human Revisions (RQ2)

This folder evaluates how effectively **AUTOCOMBAT** (powered by DeepSeek-V3.1-Reasoner) enhances programming answers compared to human revisions and existing baselines. 

It consists of two sub-folders:

---

### (a) Evaluation Findings

This sub-folder contains **five files**:

- `DeepSeek (AUTOCOMBAT).xlsx`  
- `Gemini.xlsx`  
- `Gpt.xlsx`  
- `LLaMA.xlsx`  
- `Baseline Comparison.xlsx`  

Each file includes evaluation findings of **context-aware enhanced answers** generated by the respective LLMs —  **DeepSeek-V3.1-Reasoner (AUTOCOMBAT)**, **Gemini 2.5 Flash**, **GPT-5**, and **LLaMA-4 Maverick**, based on both **syntactic** and **semantic** metrics.

The `Baseline Comparison.xlsx` file provides a performance comparison between **AUTOCOMBAT** and the existing baseline **SOUP**.

---

#### File Structure for LLM Evaluation Files  
(*DeepSeek, Gemini, GPT, and LLaMA evaluation outputs*)

| Column Name | Description |
|--------------|-------------|
| **answer_id** | Unique identifier for each Stack Overflow answer |
| **question_id** | Identifier linking the answer to its corresponding question |
| **quartile** | Indicates the quartile grouping based on comment counts |
| **revised_answer** | Human-revised version of the programming answer |
| **input_comments** | Developer comments used for improvement-related concern extraction |
| **input_initial_answer** | Original version of the answer before enhancement |
| **input_question** | The corresponding question text associated with the answer |
| **output_(model_name)** | The enhanced answer generated by the LLM |
| **output_(model_name)_meta_json** | Structured JSON output containing extracted concerns, change log, usage of question context, and the improved answer |
| **question_context_used_flag** | Binary indicator (1/0) showing whether the question context was utilized during enhancement |

---

#### File Structure for `Baseline Comparison.xlsx`  
(*AUTOCOMBAT vs. SOUP comparison results*)

| Column Name | Description |
|--------------|-------------|
| **answer_id** | Unique identifier for the analyzed Stack Overflow answer |
| **question_id** | Identifier of the associated question |
| **input_initial_answer_code** | Original (pre-enhancement) answer code snippet |
| **input_comments** | Comments containing improvement-related concerns |
| **input_question** | Question text from Stack Overflow post used as context |
| **question_context_used_flag** | Indicates if the question context was used (1 = Yes, 0 = No) |
| **revised_answer_code** | Human-revised (ground-truth) version of the answer code |
| **autocombat_output** | Code enhancement generated by AUTOCOMBAT (DeepSeek-V3.1-Reasoner) |
| **soup_output** | Code enhancement generated by the baseline model SOUP |

---

#### Evaluation Metrics

Both syntactic and semantic quality were assessed using the following metrics:

- **Syntactic Metrics:** ROUGE, BLEU, METEOR, TER, chrF, Jaccard, Distinct-n, TF-IDF Cosine Similarity  
- **Semantic Metrics:** BLEURT, COMET, BARTScore, BERTScore_F1, MoverScore  

These metrics collectively evaluate the **textual similarity**, **semantic alignment**, and **contextual accuracy** of the enhanced answers compared to human-revised ground truths.

### (b) AUTOCOMBAT Tool Integration

This sub-folder contains the **source code** and **browser integration** for the AUTOCOMBAT tool.

#### Installation & Usage Steps

  - Download the folder **AUTOCOMBAT Tool Integration** to your local drive.
  - Open the Chrome browser and go to `chrome://extensions`.
  - Enable **Developer mode** (top right).
  - Click the **Load unpacked** button and upload the `scripts` folder inside `AUTOCOMBAT Tool Integration`.
  - Activate the loaded extension (**AUTOCOMBAT 1.0**).
  - Open **Microsoft VS Code**, and open the `AUTOCOMBAT Tool Integration` folder.
  - Go to the `server` subfolder.
  - Open the VS Code terminal and run:
      ```
      pip install -r requirements.txt
      ```
  - Open the `.env` file (in the `server` subfolder) and assign your own DeepSeek API key to the `DEEPSEEK_API_KEY` variable.
  - Run the backend server:
      ```
      python app.py
      ```
  - Do not close VS Code. Minimize it and open the Stack Overflow website.
  - Choose a Python/Java/C#/JavaScript question. You will now see a button named **AUTOCOMBAT** for the corresponding answer.
  - Click the **AUTOCOMBAT** button to view the context-aware enhanced answer generated by the tool.

## (4) User Perception of AUTOCOMBAT-Enhanced Answers in Practical Settings (RQ3)

This folder contains one file:

- **`Survey Responses.csv`** – Contains the findings from a developer survey assessing the perceived effectiveness and usability of the **AUTOCOMBAT** tool.

---

### Overview

To assess **developers’ perceptions** of AUTOCOMBAT, a structured survey was conducted following the personal opinion survey guidelines by **Kitchenham and Pfleeger**.  
The survey evaluated the **ease of installation**, **effort and time reduction**, and **overall usefulness** of AUTOCOMBAT in improving Stack Overflow (SO) answers.

A total of **58 professional developers** participated, representing diverse backgrounds and experience levels:

- **Development Experience:** 1–3 years (55.17%), 4–6 years (36.21%), >6 years (8.62%)  
- **Profession:** Software Developers (52.63%), Academicians (43.85%), Students (3.52%)  
- **Stack Overflow Profile Age:** 1–2 years (33.33%), 3–5 years (38.60%), >5 years (28.07%)

---

### File Structure of `Survey Responses.csv`

| Column Name | Description |
|--------------|-------------|
| **Participant_ID** | Unique identifier assigned to each survey participant |
| **Profession** | Participant's role (e.g., Software Developer, Academician, Student) |
| **Experience_Years** | Participant’s professional experience in years |
| **Language_Evaluated** | Programming language used during AUTOCOMBAT evaluation (Python, Java, JavaScript, or C#) |
| **Ease_of_Installation** | Rated from *Very Easy (5)* to *Very Difficult (1)* |
| **Effort_Reduction** | Rated on perceived reduction in time and effort: *Significant, Moderate, Slight, Not at all* |
| **Coverage_Score** | Rating (1–5) for how comprehensively the improved answers addressed feedback |
| **Clarity_Score** | Rating (1–5) for readability and structure of the enhanced answer |
| **Relevance_Score** | Rating (1–5) for contextual and semantic alignment with the original question |
| **Likelihood_to_Use** | Likelihood of using AUTOCOMBAT in future tasks (*Very Likely, Somewhat Likely, Neutral, Unlikely, Very Unlikely*) |
| **Likelihood_to_Recommend** | Willingness to recommend AUTOCOMBAT to peers |
| **Open_Feedback** | Participants’ qualitative suggestions or remarks about AUTOCOMBAT’s usability and improvement areas |

---

### Key Findings (from the Paper)

**Ease of Installation**  
- *25.9%* rated “Very Easy”  
- *44.8%* rated “Easy”  
- *24.1%* rated “Moderate”  
- *5.1%* rated “Difficult”

**Effort and Time Reduction**  
- *48.3%* reported a “Significant” reduction  
- *39.7%* reported a “Moderate” reduction  
- *11.0%* reported a “Slight” reduction  


**Overall Recommendation**  
- **84.5%** of participants indicated they would **use or recommend AUTOCOMBAT** in practice.

---

### Summary of Insights

- AUTOCOMBAT was found to be **easy to install**, **time-efficient**, and **highly effective** across experience levels.  
- Developers particularly appreciated its **clarity** and **coverage** in enhanced answers.  
- Feedback highlighted minor improvement areas such as automating installation, expanding language support, and improving code generation consistency.  
- Overall, the tool demonstrated **high usability**, **broad acceptance**, and **strong real-world adoption potential** among developers.
